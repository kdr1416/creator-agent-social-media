# Routing and asset contracts

## Timing and engine selection

Preserve immutable raw audio/transcript evidence. Use sample-aligned scene bounds, `raw_text` and separate fact-checked `corrected_text` in the project scene manifest. Review the entire film before detailed assets. Record scene engine, capability reason and any later routing override. Do not force engine ratios or change engines merely to get a style.

HyperFrames and conditional Remotion support character, product, typography, infographic and abstract scenes. Select by compatibility, existing components and needed capability. Legacy `HF_ONLY`, `FLOW_ONLY`, `HYBRID` labels may be preserved with an explicit renderer field. A pure 2D film may use 100% deterministic composition without reconsidering a quota or calling Flow.

Only when the project requires generated media, evaluate Flow or a generated-media/compositor combination. Check health/provider status then, follow the applicable API skill, and inspect plates before planning exact overlay timing. Do not use generation as automatic wallpaper.

## Storyboard and asset contract

Each scene records its ID, source timing, engine/reason, narrative purpose, visual action, opening/change/final states, timed beats, visible text, assets with provenance, render entry/output and QA plan. Put style-specific fields in the project storyboard as needed. Character action, container inventory, accents, mobile plan and dark-mass strategy are useful when relevant, not compulsory empty paperwork.

Resolve every required asset before rendering. Preserve semantic IDs and separate independently animated parts where the scene needs them. Reuse suitable assets/components from approved pilot work; new ones are allowed within approved constraints. Missing assets must be reported rather than hidden by an unrelated fallback.

Store approved shared constraints and pilot evidence in persistent production state. Changes to those require renewed human review. A scene-only edit should invalidate that scene's render/QA and final assembly without rewriting the rest of the project.
